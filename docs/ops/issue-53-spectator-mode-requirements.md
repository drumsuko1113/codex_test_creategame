# Issue #53 観戦モード要件定義

## 背景
- 現在は参加者のみが対局状態を確認でき、第三者が進行を閲覧できない。
- 配信やレビュー用途では、読み取り専用で局面を追従できる導線が必要。

## 目的
- 対局に参加しないユーザーが、`gameId` を指定して対局を観戦できるようにする。
- 観戦者は局面表示のみ可能とし、対局操作は完全に無効化する。

## スコープ
- 観戦開始導線
  - セットアップ画面から `gameId` を入力して観戦開始できること。
  - 観戦URL（`?spectate=<gameId>`）を生成できること。
  - 観戦URLアクセス時に観戦対象 `gameId` を解決できること。
- 観戦表示
  - 盤面 / 持ち駒 / 手番 / 結果を表示できること。
  - 参加者セッションがない状態でもスナップショット同期が継続すること。
- 観戦操作抑止
  - 着手、駒打ち、成り選択、投了など対局操作が発火しないこと。
  - 観戦中は対局制御ボタン（投了・一時停止・局面再取得）を無効化すること。
- 更新追従
  - ポーリングで局面更新に追従すること。
  - オフライン/オンライン復帰時の再同期が機能すること。

## 非スコープ
- 観戦チャット
- 観戦者ごとの高度な権限管理
- ルーティング基盤の刷新

## 技術方針
- `lobbyValidation` に観戦フォームバリデーションを追加する。
- 観戦URLの生成/解析は `online/spectatorLink` に分離する。
- Appでは `onlineGameId = session?.gameId ?? spectatorGameId` を導入し、
  参加者/観戦者で同期処理を共通化する。

## 受け入れ条件
1. 観戦者は `gameId` 指定で対局に参加せず閲覧できる。
2. 観戦URL（`?spectate=<gameId>`）で観戦対象を指定できる。
3. 観戦者は着手/投了など対局操作を実行できない。
4. 対局進行に応じて観戦画面が追従更新される。

## 検証計画
1. 単体テスト
- 観戦フォームバリデーション（空入力/trim 正常系）
- 観戦URL生成/解析（生成、trim、空値）

2. 回帰テスト
- `npm test`
- `npm run build`

3. 手動確認
- 1つのクライアントで対局進行し、別クライアントで観戦して更新追従を確認
- 観戦側で盤面クリック/駒打ち/投了が発火しないことを確認
