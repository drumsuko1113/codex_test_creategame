# Issue #38 対局作成/参加画面 要件定義

## 背景
- 現状フロントはローカル対局前提で、オンライン対戦開始に必要な導線が不足している。

## 目的
- ユーザーがUI操作だけで対局作成・対局参加できるようにする。
- 参加成功時にセッション情報（`gameId`, `sessionToken`, `seat`）をクライアント状態へ保持する。

## スコープ
1. 作成フォーム
- `mainMinutes`, `byoSeconds` を入力して `POST /api/games` を呼び出す。
- 成功時に `gameId`, `joinToken` を画面表示する。

2. 参加フォーム
- `gameId`, `joinToken`, 表示名, 席（black/white）を入力して `POST /api/games/{gameId}/join` を呼び出す。
- 成功時に `gameId`, `sessionToken`, `seat` をクライアント状態に保存し、対局画面へ遷移する。

3. エラー表示
- API失敗時は `error.code` を優先して人が理解できる文言へ変換して表示する。
- 通信失敗時はネットワークエラーとして明示する。

4. クライアント入力バリデーション
- 作成: `mainMinutes` は 1 以上の整数、`byoSeconds` は 0 以上かつ 10 秒単位。
- 参加: `gameId` 必須、`joinToken` 必須、表示名 2..20 文字、席の選択必須。

## 非スコープ
- 観戦モード
- WebSocket同期
- API駆動の着手反映（Issue #39）

## 受け入れ条件
1. 画面操作のみで対局作成できる。
2. 画面操作のみで対局参加できる。
3. APIの `4xx/5xx` を理解可能な文言で表示できる。
4. クライアントバリデーションが作動し、不正入力ではAPIを呼ばない。
5. 参加成功時にセッション情報がアプリ状態へ保存される。

## テスト方針（TDD）
1. Red
- バリデーション関数の失敗/成功をテスト追加。
- APIクライアントのリクエスト内容、エラーマッピングをテスト追加。

2. Green
- バリデーション関数とAPIクライアント実装。
- Setup画面を作成/参加UIへ置換し、Appに状態遷移を実装。

3. Refactor
- UIハンドラ責務を整理し、表示ロジックを最小化。

4. Regression
- `npm test`
- `npm run build`
