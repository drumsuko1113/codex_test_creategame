# Issue #50 要件定義（ネットワーク障害時の再試行/復帰UX）

## 背景
- オンライン対戦では一時的なネットワーク断が起きる前提であり、無言停止は操作継続性を損なう。

## 目的
- 通信失敗時に状態を可視化し、手動再試行または自動再試行で復帰できる UX を提供する。

## スコープ
1. 通信失敗の可視化
- 通信失敗時にエラーバナーを表示する。
- オフライン時は専用メッセージに切り替える。

2. 手動再試行
- バナー上に再試行ボタンを表示し、同期 API を即時再実行できるようにする。

3. ポーリング再試行のバックオフ
- ポーリング失敗時に次回間隔を指数バックオフする。
- 上限時間を設定し、過度な待機にならないようにする。
- 成功時に失敗回数をリセットする。

4. オンライン/オフライン連動
- `offline` イベントで障害表示を開始する。
- `online` イベントで復帰通知し、自動同期を試行する。

## 非スコープ
- サーバ監視基盤（APM）導入。
- WebSocket による恒久的再接続制御。

## 受け入れ基準
1. 通信失敗時に必ず障害メッセージが表示される。
2. 再試行操作で同期復帰が可能である。
3. 一時障害でページ再読込が必須にならない。

## TDD 方針
1. Red
- ネットワークエラー判定とバックオフ計算のユニットテストを追加して失敗させる。

2. Green
- 判定/計算モジュールを実装し、`App` にバナー、再試行、バックオフ制御を統合する。

3. Refactor
- 復帰ロジックを専用モジュールへ分離し、`App` の責務を単純化する。

4. Regression
- `npm test`
- `npm run build`
