# Issue #41 要件定義（非手番時の盤面操作無効化）

## 背景
- API 駆動化後、非手番でも盤面クリックや持ち駒操作を試行できると、UX と状態整合性の両方で混乱が起きる。
- サーバ側は拒否できるが、クライアント側でも事前に操作不可を明示し、不要な API リクエストを防ぐべき。

## 目的
- 自席と現在手番を判定し、非手番では着手関連操作を発火させない。
- 非活性状態を UI で明示し、ユーザーが「今は操作不可」と即座に判別できるようにする。

## スコープ
1. 入力制御
- 非手番中は盤面クリック、持ち駒選択、着手送信を無効化する。

2. 視覚表現
- 盤面・持ち駒を非活性スタイル（cursor / opacity）で表示する。
- 非手番中の説明文を表示する。

3. フォールバック表示
- サーバから `NOT_YOUR_TURN` / `UNAUTHORIZED` / `VERSION_CONFLICT` 等が返る場合は、既存のエラーメッセージ表示を維持する。

## 非スコープ
- 観戦モード専用 UI。
- WebSocket 化や高度な再接続制御。

## 受け入れ基準
1. 非手番中は着手操作が発火しない。
2. 非手番中であることが UI で視覚的に分かる。
3. 手番復帰直後に操作を再開できる。

## TDD 方針
1. Red
- 手番操作可否判定と非手番メッセージ判定のテストを先に追加して失敗させる。

2. Green
- 判定ロジックを `turnControl` モジュールに実装し、`App` / `Board` / `Hand` へ適用する。

3. Refactor
- 操作可否の条件を UI から分離して責務を明確化する。

4. Regression
- `npm test`
- `npm run build`
