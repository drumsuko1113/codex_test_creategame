# Issue #40 要件定義（ポーリング同期）

## 背景
- 手動の「再取得」だけでは、相手の着手を見落として盤面が古いままになる。
- 対局画面では自動で最新局面に追従し、操作ミスや認識差分を減らしたい。

## 目的
- 対局中に一定間隔でスナップショット API を呼び出し、最新局面を取り込む。
- 既存の手動再取得ボタンはそのまま維持する。

## スコープ
1. ポーリング間隔
- 画面表示中は 2 秒間隔。
- 非表示タブでは 3 秒間隔。

2. 反映条件
- 取得した `version` が現在より進んでいる場合のみ盤面を更新する。
- 同一 `version` または古い `version` は破棄する。

3. 実行条件
- 対局画面 (`screenMode = game`) かつ `session` が存在し、`gameOver = false` のときのみ実行する。
- setup 画面、ゲーム終了後、アンマウント時には停止する。

4. エラー方針
- バックグラウンドポーリングの失敗は UI メッセージを上書きしない。
- 次周期で再試行する。

## 非スコープ
- WebSocket 化。
- 複雑な再接続制御や指数バックオフ（別 Issue で対応）。

## 受け入れ基準
1. 対局中、相手の着手が最大 3 秒以内に盤面へ反映される。
2. `version` が進んでいないレスポンスでは盤面更新が発生しない。
3. setup 画面やゲーム終了後はポーリングが動作しない。

## TDD 方針
1. Red
- ポーリング間隔と反映条件のユニットテストを先に追加し、失敗を確認する。

2. Green
- 方針関数を実装し、`App` にポーリング effect を追加する。

3. Refactor
- 方針関数を `pollingPolicy` に分離し、責務を明確化する。

4. Regression
- `npm test` と `npm run build` を通す。
