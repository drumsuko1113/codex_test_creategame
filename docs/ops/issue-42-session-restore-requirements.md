# Issue #42 要件定義（リロード/再接続時の対局復元）

## 背景
- ブラウザ再読込や一時切断で対局状態が失われると、オンライン対戦の継続性が低下する。
- セッション情報を保持し、起動時に自動復元できる必要がある。

## 目的
- `gameId + sessionToken + seat` を保存し、再読込後に同一対局へ復帰できるようにする。
- 無効トークン時は安全に復元を中止し、再参加導線を提示する。

## スコープ
1. セッション保持
- `gameId` / `sessionToken` / `seat` / `displayName` をローカルに保存する。
- 読み出し時は型検証し、不正データは破棄する。

2. 参加状態確認
- 認証付きの確認 API（`GET /api/games/{gameId}/me`）でセッション有効性を確認する。

3. 復元フロー
- 起動時に保存セッションを読み込み、`/me` 成功後に snapshot を取得して対局画面へ復帰する。
- 失敗時（401/404 など）は保存セッションを削除し、setup画面で再参加を案内する。

## 非スコープ
- 長期認証基盤の刷新。
- WebSocket 再接続制御。

## 受け入れ基準
1. リロード後に同一対局へ自動復帰できる。
2. 無効/期限切れトークン時に復元失敗を明示し、再参加へ誘導できる。
3. 復元後の手番・持ち時間・勝敗状態が snapshot と一致する。

## TDD 方針
1. Red
- セッション保存/復元ユーティリティのテストを先に追加して失敗させる。
- `/me` API のクライアント/サーバテストを追加して失敗させる。

2. Green
- セッション永続化モジュール、`/me` API、`App` の復元フローを実装する。

3. Refactor
- 復元関連ロジックを UI から分離し、責務を明確化する。

4. Regression
- `npm test`
- `npm run build`
